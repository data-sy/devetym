# 피드백 아카이브 — 접수 규칙

사람에게 받은 피드백 **원문**을 보관하는 곳. 이 repo는 **공개**이므로, 공개돼도 무해한 형태로만 커밋한다.

## 규칙 1 — 익명화는 접수 시점에 한 번

git 이력은 불변이라 **커밋 후 익명화는 소용없다.** 파일에 처음 옮겨 적을 때 아래를 제거·치환한다.

- 이름·연락처·소속·직장 → `P1`, `P2` … 코드로
- 특정 가능한 맥락(어느 회사 팀 얘기, 개인 사정 등) → 삭제하거나 일반화
- 스크린샷은 알림·연락처·계정명이 찍혔는지 보고 올린다

코드 ↔ 실명 매핑이 필요하면 `private/`에 둔다(아래).

## 규칙 2 — 공개 곤란한 건 `private/`

`docs/feedback/private/`는 **`.gitignore`로 통째 제외**된다. 익명화해도 공개하기 곤란한 원문·매핑표·스크린샷은 여기 둔다.

⚠️ **여기 있는 파일은 git이 백업하지 않는다** — 이 맥북에만 존재한다. 잃으면 곤란한 건 별도로 백업할 것.

공개 파일에는 요약과 도출된 액션만 남기고, 필요하면 `→ private/xxx.md` 로 가리킨다.

## 규칙 3 — 역할 경계

| 무엇 | 어디 |
|---|---|
| 피드백 **원문**(시간 안 타는 기록) | 여기 `docs/feedback/` |
| 고칠 **액션 아이템**(시점성 상태) | GitHub Issues ([ADR-0008](../adr/0008-issue-tracking.md)) |
| 그로 인한 **결정·설계** | `docs/specs/`, `docs/adr/` |

원문을 이슈에 복붙해 두지 않는다 — 이슈는 닫히면 묻히고, 원문은 남아야 한다. 이슈에서 이쪽 파일을 링크한다.

## 파일 이름

`YY-MM-DD-<채널>.md` — 예: `26-07-13-실기기-2차-3차.md`, `26-08-10-웹-지인.md`

각 파일 머리에 **언제·어느 채널·누구(코드)·무엇을 보고** 받은 피드백인지 한 줄 적는다. 맥락 없는 피드백은 나중에 해석이 안 된다.
