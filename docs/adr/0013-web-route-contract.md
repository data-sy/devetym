# ADR 0013: 웹 라우트 계약 — SSG + 생성 금지 SSR 폴백, 색인은 품질 게이트가 연다

## Status
**Accepted** (2026-08-25 발의 · **2026-08-25 사람 비준**) — [ADR-0009](0009-web-framework-rendering.md) Decision 1의 렌더링 문장을 **구체화**한다(뒤집지 않는다). [ADR-0012](0012-content-canon-d1.md)(콘텐츠 정본 D1 승격)를 전제로 한다.

**함께 정해진 것 (2026-08-25 사람)**: 이 ADR의 Negative가 지적한 「승격 잡이 없으면 생성분은 영원히 `noindex`」를 **W1b 다음 W1c로 W 트랙 안에서 닫는다**(선택지 (b)). 승격 잡 없이 웹을 종결하지 않는다.

## Context

[ADR-0009](0009-web-framework-rendering.md) Decision 1은 이렇게 적혀 있다:

> 용어 상세 650개는 **SSG**. AI가 새로 생성한 용어는 on-demand 서버 렌더 후 D1에 적재되어 이후 정적처럼 서빙된다.

두 번째 문장이 **누가 그 서버 렌더를 유발하는가**를 말하지 않는다. 착수 시점에 이 공백은 세 갈래로 갈린다.

사람 질문(2026-08-25): *"3중 리드 구조를 만들어 뒀는데도 650개를 같이 쏴두는 게 필요해? 웹은 그냥 프록시 서버를 거쳐가면 되는 거 아닐까?"*

**질문이 두 개로 나뉜다.**

- **데이터 경로**: 맞다. 웹이 콘텐츠 사본을 들고 있을 이유가 없다. [ADR-0012](0012-content-canon-d1.md)가 이를 해소한다.
- **URL 존재 여부**: 이건 데이터 전달 결정이 아니라 **W 트랙의 존재 이유**다. 검색엔진이 색인하는 것은 API 응답이 아니라 URL이다. 페이지 내용이 브라우저 fetch로 도착하면 크롤러는 빈 껍데기를 본다 → 색인 0장 → 유입 목적이 무너진다. **서버가 HTML을 채워 내보내는 650개 URL 자체는 양보 대상이 아니다**(ADR-0009 Decision 3이 Kotlin/Wasm을 기각한 것과 정확히 같은 논거).

동시에 두 개의 실재하는 위험이 있다.

- **T6 · 크롤러가 과금 수도꼭지가 된다.** "미보유 용어 URL에 접근하면 생성한다"로 구현하면, Googlebot이 `/term/<무엇이든>`을 긁는 순간 Claude 호출이 열린다. Turnstile·3건 한도는 **사용자 개시 POST**에 걸려 있어 GET 라우트를 보호하지 않는다. 웹 전역 30건/일 캡이 하루치를 크롤러가 태우고 끝낸다.
- **T7 · 미검수 얇은 콘텐츠 대량 색인.** authored 650조차 **317개(48.8%)가 300자 미만**이다. 여기에 검수 안 거친 생성분을 색인 대상으로 풀면 사이트 전체 품질 신호를 스스로 훼손한다.

## Decision

**용어 URL은 SSG를 기본으로 하고, 그 위에 조회 전용 SSR 폴백을 둔다. 색인 자격은 품질 게이트가 연다.**

1. **SSG의 입력은 커밋된 스냅샷이다** — D1 직접이 아니라 [ADR-0012](0012-content-canon-d1.md) Decision 5의 `terms.json` 스냅샷. 빌드가 D1 가용성에 묶이지 않고 재현 가능하며, 무엇이 정적으로 나갔는지가 git에 남는다.

2. **`/term/<key>` SSR 폴백은 D1 조회 전용이다. 생성을 트리거하지 않는다.** D1에 없으면 **404**다. 이것이 이 ADR의 핵심 방어선이다(T6). 생성은 오직 **사용자 개시 경로**(Turnstile 토큰 + 쿠키 3건/일 + IP 15건/일 + 웹 전역 30건/일, [ADR-0010](0010-web-abuse-prevention.md))에서만 일어난다.

3. **생성 성공 직후 그 용어는 자기 URL을 갖는다.** 생성분이 정본 테이블에 적재되므로([ADR-0012](0012-content-canon-d1.md)) SSR 폴백이 즉시 서빙한다 — 공유 가능한 링크가 그 자리에서 생긴다.

4. **색인 자격 = 품질 게이트 통과 여부.**

   | 라우트 | 대상 | 색인 | 사이트맵 |
   |---|---|---|---|
   | SSG | `origin='authored'` 스냅샷 | **indexable** | 포함 |
   | SSR 폴백 | `origin='generated'` (미승격) | **`noindex`** | 제외 |

   승격 잡(INV-7의 `critic` = 승격 시점 게이트)을 통과하면 `origin`이 `authored`로 올라가고, **다음 빌드에서 SSG 집합에 편입되며 그때 색인된다.** 즉 **품질 게이트가 곧 색인 게이트다** — 별도 SEO 정책을 발명하지 않고 이미 있는 분리(INV-7)를 재사용한다.

5. **미보유 용어는 404 + 「AI에게 물어보기」 어포던스.** 200 빈 페이지(soft 404) 금지 — 크롤러에게 "내용 없는 페이지가 무한히 있는 사이트"로 읽힌다.

6. **사이트맵은 SSG 집합만 담는다.** 크롤러를 `noindex` 페이지로 안내하지 않는다.

## Consequences

### Positive
- **캐시 플라이휠이 SEO 플라이휠이 된다.** 누군가 새 단어를 물으면 정본에 굳고, 승격을 통과하면 색인되는 페이지가 하나 늘어난다. 콘텐츠가 사용에서 자란다.
- **크롤러가 비용을 태울 수 없다.** GET 경로에 생성이 없다.
- **색인 품질이 검수와 동기화된다.** 얇거나 틀린 생성분이 검색 결과에 나가지 않는다.
- **빌드가 D1에 묶이지 않는다.** D1이 죽어도 사이트는 배포·서빙된다(SSR 폴백만 열화).

### Negative
- **플라이휠이 승격 잡에 종속된다. 그리고 승격 잡은 아직 없다**(캐시 M5 = CMP M8, 미착수). 승격 잡이 없으면 생성분은 **영원히 `noindex`**이고, 이 ADR의 최대 이점이 잠긴 채로 남는다. → 착수 순서에 반드시 반영할 것.
- **빌드 주기가 색인 지연이 된다.** 승격과 색인 사이에 최소 1회 빌드·배포가 낀다.
- 라우트가 둘(정적 자산 + SSR 핸들러)이라 캐시 헤더·404 처리가 두 곳에서 정합해야 한다.

### Neutral
- ADR-0009의 스택 결정(Astro·React 아일랜드·Cloudflare)은 무변경. 이 ADR은 그 위의 라우트 계약만 정한다.
- `noindex` 페이지도 사람에게는 정상 동작한다 — 씨딩·공유 링크는 색인과 무관하게 성립한다.

## Alternatives Considered

1. **전면 SSR(정적 없음)** — 사용자 질문의 문면("프록시를 거쳐가면 되지 않나")에 가장 가까운 형태. 그러나 D1이 **사이트 가용성의 단일 장애점**이 되고, ADR-0009가 SSG로 얻으려던 것(JS 없는 즉시 렌더·Core Web Vitals)을 통째로 반납한다. **기각.**
2. **SSG만 (ADR-0009 문면 그대로 좁게 읽기)** — 생성분이 페이지가 되지 못해 캐시 플라이휠이 유입에 기여하지 않는다. **기각.**
3. **SSR 폴백에서 미보유 용어 생성 트리거** — 구현이 가장 단순하고 UX도 매끄럽다. 그러나 크롤러 1회 크롤로 웹 전역 캡이 소진된다(T6). **기각 — 이 기각을 명시적으로 기록한다.** 구현 중 "폴백에서 그냥 생성하면 되지 않나"로 되돌아오기 쉬운 지점이다.
4. **생성분도 즉시 색인** — 페이지 수가 빨리 는다. 그러나 검수 안 된 얇은 콘텐츠를 대량 색인해 사이트 품질 신호를 훼손한다(T7). authored조차 48.8%가 300자 미만인 상황에서 감당할 수 없는 교환. **기각.**
5. **클라이언트 렌더 + prerender 서비스** — 크롤러에만 다른 응답을 주는 형태. 클로킹 위험·운영 복잡도·비용. **기각.**
