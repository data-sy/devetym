# ADR 0010: 웹 AI 폴백 남용 방지 경계 — 표면 분리 + Turnstile + 3층 한도

## Status
**Accepted** (2026-08-25) — 설계 위원회 산출(2026-08-05 `Proposed`), 2026-08-25 사람 비준 — 웹 AI 폴백을 여는 「크게」 확정으로 이 경계가 W1a 임계경로가 됨.

근거 정본: [`../design/web-transition-design.md`](../design/web-transition-design.md) §4 (결정 D5·D6) — 특히 §4-3(INV-1 저촉 검토)·§4-5(캡 설정값)·§4-6(전환 경로와 대가).

## Context

웹 표면에서도 AI 폴백(번들에 없는 용어를 Claude로 생성)을 연다 — **사람 결정(2026-08-05)**. 근거: *"AI로 원하는 어원을 다 설명해준다가 제품 정체이며 그것이 없으면 의미가 없다."*

이 결정이 여는 비용 면을 다뤄야 한다. 실측한 현행 상태:

- 프록시(`devetym-proxy/src/index.js`)에 **기기당 `DAILY_LIMIT = 10`** + **전 기기 합산 `GLOBAL_DAILY_LIMIT = 200`**이 이미 구현돼 있다. `X-Device-Id` 위조 우회에 대한 방벽은 **이미 서 있다** — `docs/cost/cost-management-decision.md`가 이 위협을 이미 인지·기록하고 있다.
- **캐시 히트는 한도 검사를 통과하지 않는다**(비준 B4). D1에 있는 용어는 무과금·무한도로 서빙된다.
- **CORS 헤더가 전혀 없다** — 브라우저는 현재 프록시를 호출할 수 없다.
- Anthropic 조직 월 spend limit **$30**. 7월 실적 $0.20.

따라서 남은 문제는 헤더 위조가 아니라 **표면 간 전이**다: 익명 웹 트래픽이 앱과 같은 캡·같은 예산을 태우면, **이미 App Store에 게시된 iOS 앱 사용자가 429/402를 받는다.** 프록시 주석(`src/index.js:138`)이 이 경로를 이미 인지하고 있다.

추가 제약: 웹에는 앱의 `X-Device-Id`에 해당하는 것이 없고 위조 불가능한 식별자는 IP뿐인데, **한국 모바일 통신사는 CGNAT을 광범위하게 쓴다** — 단일 IP 한도는 모바일 유입 사용자끼리 서로의 몫을 잠식한다.

## Decision

**웹 표면을 앱 표면과 격리하고, 4겹 방어 + 3층 한도로 연다.**

### 1. 4겹 방어

1. **Turnstile** — 웹의 *생성* 요청에만 토큰을 요구한다. 정적 페이지 열람·캐시 히트에는 요구하지 않는다(유입 마찰 0).
2. **표면 분리 캡** — 웹 전용 전역 캡을 앱 캡과 **별도로** 둔다. 웹이 자기 몫을 다 태워도 앱 몫 200은 남는다.
3. **IP 기반 한도** — `CF-Connecting-IP`는 Worker가 직접 보는 값으로 클라이언트가 위조할 수 없다.
4. **Anthropic 워크스페이스 분리 + 워크스페이스별 spend limit** — `cost-management-decision.md`가 "원리 1"로 제안해 두고 미적용이던 항목. **이제 적용 트리거가 발생했다.**

### 2. 3층 한도 (웹)

| 층 | 기준 | 값 | 성격 |
|---|---|---|---|
| 사용자 대면 | 브라우저(쿠키/localStorage) | **3건/일** | UX 한도 + **앱 유도 전환점**. 리셋 가능하나 아래가 받친다 — 의도된 느슨함 |
| 남용 방지 | IP(`CF-Connecting-IP`) | **15건/일** | CGNAT 공유를 감안한 백스톱 |
| 예산 | 웹 전역 | **30건/일** | 비용 상한 |

앱 측은 현행 유지(기기당 10 / 전역 200). **앱 전역 200은 예산 상한이 아니라 폭주 차단 회로차단기**이며, 실제 예산 강제는 Anthropic spend limit이 맡는다.

### 3. CORS

우리 웹 오리진만 **고정 allowlist**로 허용한다. Origin 동적 에코 금지. Preflight 처리.

### 4. 예산

**$30 유지로 시작**한다. 상향이 필요해지는 상황은 유입이 붙었다는 신호이며 그때 정당화된다. 선제 상향은 하지 않는다.

## Consequences

### Positive
- 웹의 비용 사고가 앱으로 전이되지 않는다 — 이 설계에서 가장 무거운 위험의 차단.
- 3건 한도가 **웹 → 앱 전환 경로**를 만들고 측정 가능하게 한다(한도 도달 → 앱 링크 클릭률). 설계상 비어 있던 자리를 메운다.
- CORS allowlist가 제3자 사이트의 무료 게이트웨이화(T4)를 막는다.
- `INV-1`(앱 코드 무변경)이 유지된다 — 위 변경은 전부 서버 측이다.

### Negative
- **⚠️ 부분 격리다.** 표면 구분을 `Origin` + Turnstile 토큰으로 하면 브라우저는 위조 못 하지만 **`curl`은 Origin을 안 보내거나 위조해 "앱"으로 위장**할 수 있다. 완전 격리는 앱 요청에도 검증 가능한 서명을 요구하는데 **그것은 INV-1을 깬다.** 수용 근거: curl 위장은 지금도 가능하고 지금도 200에서 막히므로 **웹 개방이 이 경로를 악화시키지 않는다.** 완전 격리는 다음 앱 릴리즈로 이월한다.
- **웹은 "다 설명해준다"를 제공하지 않고 "3개까지 증명해 보인다"를 제공한다.** AI 폴백을 W1에 연 근거(D5)를 부분적으로 되돌린다. 이 교환은 사람이 인지한 상태에서 채택되었다(2026-08-05).
- 한도 도달 화면이 정상 사용자가 만나는 화면이 된다 — 문구 설계가 필요하다(설계서 Q4).
- **캐시 오염(T5)**: 봇의 무작위 입력이 D1에 write-once로 굳으면 INV-2가 재생성을 금지하므로 정정할 수 없다. `NotDevTerm`은 저장하지 않아 부분 완화되나, **서버 write-back 분기 정책은 미확인**이다(설계서 §8-4).

### Neutral
- Turnstile 통과율이 정상 사용자에게 유의미한 마찰을 만들면 IP 한도 + WAF 단독으로 후퇴할 수 있다.

## Alternatives Considered

1. **웹에서 AI 폴백 차단(정적 650개만)** — 비용 노출 0, 구현 최소. **사람이 기각**: 제품 정체를 제공하지 못한다.
2. **D1 캐시 읽기 전용(생성은 앱 전용)** — 비용 노출 0. 기각: 7월 실적($0.20)에서 역산하면 D1 누적 생성량이 수십 건 미만으로 추정돼 **실질적으로 "차단"과 같다.**
3. **W2로 지연 개방** — 출시 직후는 색인 전이라 방문자가 거의 없어 AI의 효용이 낮고 위험만 크다는 논리. 기각: 첫인상이 한 번뿐이고, 반쪽 제품으로는 위키·블로그 대비 이길 각도(무한 커버리지)를 보여주지 못한다.
4. **계정 + 쿼터** — 유입에 마찰이고, 개인화 웹 v1 제외 결정과 불일치. 기각.
5. **현행 `X-Device-Id` 그대로 웹 개방** — 브라우저에서 자유 위조 + 앱으로의 전이. 기각.
